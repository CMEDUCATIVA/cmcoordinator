# Actualizaciones de Cmcoordinator desde Settings

Versión del documento: 0001

## Uso

En Revit, abrir Settings → Actualizaciones → Actualizar desde GitHub. La consulta es pública y no usa el token del CDE. El botón busca la última Release estable, compara la versión instalada y descarga un instalador con tamaño y SHA256 comprobados. Cerrar Settings cancela una descarga en curso; no cancela una instalación ya preparada.

Al terminar, guardar el modelo y cerrar voluntariamente todas las instancias de Revit. Un helper independiente abre entonces el instalador oficial. Windows puede pedir elevación; el instalador conserva su interfaz para revisar componentes y continuar o cancelar. No se cierran procesos de Revit por fuerza ni se reemplaza una DLL mientras esté cargada. No es una instalación silenciosa ni una actualización en caliente.

## Contrato de publicación en GitHub

- Repositorio público: CMEDUCATIVA/cmcoordinator.
- Crear una Release estable publicada, no borrador ni prerelease. Una etiqueta o un commit sin Release no ofrece instalador.
- Etiqueta numérica, por ejemplo `v2026.10.1` o `v1.2.3`; la versión de las DLL debe avanzar de forma coherente con la etiqueta. No usar etiquetas descriptivas sin número ni degradar versiones.
- Adjuntar exactamente un instalador EXE cuyo nombre empiece por `Cmcoordinator`. Debe corresponder a los targets soportados y contener el complemento, visor y `Updater/apply-update.ps1`.
- El asset debe estar uploaded y tener tamaño y digest `sha256:` válidos en la API de GitHub. El tamaño máximo admitido es 512 MiB. No se ejecutan archivos ZIP, código fuente o un EXE de otro repositorio.
- Al publicar, conservar los prerrequisitos de Node y del runtime IFC documentados para el visor. Este actualizador no los instala por sí mismo.

El instalador se obtiene del asset, no del enlace a la página web del Release. Al usar una etiqueta nueva con una versión superior se prepara la actualización. Después de la primera instalación registrada, una sustitución del asset/digest bajo la misma etiqueta también se detecta, siempre que el recibo corresponda al hash de la DLL instalada. Cambiar solo las notas de la publicación no requiere reinstalar.

## Estados y recuperación

Sin Release estable: aviso y ningún instalador iniciado. Sin red, límite API, descarga incompleta, hash incorrecto o cancelación: estado de error/cancelación y reintento permitido. Nunca promover un `.part` a instalador completo si falla la validación.

Preparada: espera hasta 24 horas al cierre de Revit; un lease permite solo un helper instalador. El helper vuelve a comprobar SHA256 antes de iniciar el EXE. El instalador también verifica si se reabrió Revit. No se escribe recibo de actualización si el EXE falla, se cancela o no cambia la DLL de esa instalación.

Datos propios bajo `%LOCALAPPDATA%/Cmcoordinator/Updates`: carpetas de descarga por trabajo, pending.json, update.log y recibos por ruta de instalación. Se conservan descargas fallidas para diagnóstico; no se incluyen en Git. El recibo vincula tag, asset/digest y hash real de DLL. Si la DLL cambia fuera de ese proceso, el recibo anterior no acredita la versión instalada.

## Límites de comprobación inicial

Cliente/descarga/recibo probados con respuestas controladas, XAML cargado sin invocar Revit y helper comprobado por parser PowerShell. La instalación completa por Release real requiere que exista una publicación con instalador; no se crea una Release solo para simular éxito. El workflow de GitHub permanece manual, sin distribución automática. Las actualizaciones del código no equivalen a una Release publicada.

Fuente del contrato de GitHub: [REST API de Releases y assets](https://docs.github.com/en/rest/releases/releases).
